# 架构与资源控制

[项目首页](../README.md) · [使用指南](USER_GUIDE.md) · [构建说明](BUILD.md) · [验证记录](VALIDATION.md)

本地图像工具采用 Rust 工作区，桌面界面与命令行共用处理核心。目标负载为每批 1000 张、单张约 2400 万像素的网页、电商、截图和手机照片；内存优先于吞吐量。启动空闲目标为 100 MiB，处理峰值目标为 2048 MiB，均需要在目标机器上实测。

## 目录与职责

| 目录 | 职责 |
| --- | --- |
| `crates/image-core/` | 图像识别、导入、来源校验、色彩与元数据、编码、批量调度和输出提交 |
| `crates/desktop/` | egui/eframe 原生界面、独立工具会话、设置、后台任务与受限预览 |
| `crates/cli/` | `lit` 命令行入口、批处理报告与确定性样本生成 |
| `assets/` | 应用图标、离线中文字体子集及许可 |
| `packaging/` | 平台资源、安装模板和第三方许可收集 |
| `scripts/` | 构建打包、格式验证和可选性能测量 |
| `docs/` | 使用、构建、验证与架构决策 |

构建目录 `target/`、本地工具链 `.tools/`、分发包 `dist/`、验证输出 `artifacts/` 均不纳入 Git。自动化测试保留在对应 crate 中；测试输入在临时目录生成，截图、处理结果和日志不随源码分发。

## 独立工具与输入来源

首页提供压缩图片、调整尺寸和转换格式三个独立入口。`tool.rs` 定义各自的偏好与请求生成规则：压缩保持输入格式、像素尺寸与动画；调整尺寸保持格式与动画；转换格式保持像素尺寸。每项工具有独立参数、选择、队列和结果。语言、输出位置与递归导入选项共用。

`app.rs` 切换工具会话，`worker.rs` 在后台导入、检查来源和处理文件。准备检查使用取消标记、请求代次和工具标识；导航可以取消检查，过期回复不能改动新会话。尚未检查完的跨工具续作取消时，仅撤回本次新增条目并恢复原有选择。检查完成后，传入项保留，用户明确开始才执行。实际处理、导入或原生文件对话框期间暂不切换工具。

每个输入分别记录最初原图与本次实际输入。“重新调整”读取原图；“继续调整”读取选中的成功输出并保留原图来源。例如原图 4000×3000 先缩到 2000×1500，继续按 50% 缩放得到 1000×750；从原图重新按 50% 调整则得到 2000×1500。参见 [来源关系决策](adr/0001-reprocessing-inputs.md) 和 [术语表](../CONTEXT.md)。

## 图像处理

核心先识别真实格式并检查尺寸、帧、色彩及资源需求，再选择处理路径。JPEG 使用 MozJPEG，PNG 使用 PNG 编解码与 oxipng，WebP 使用 libwebp，GIF 使用 Rust `gif` 库。缩放使用 `fast_image_resize`，色彩转换使用 `moxcms`。

纯无损优化与需要像素重编码的操作分开处理。JPEG 无损优化保留系数与量化表；PNG 保留支持的位深；GIF 逐帧合成，处理时长、循环和处置方式。动画转静态图必须显式选择首帧。元数据默认移除非显示必需部分，方向与颜色处理独立于这个开关。

不支持的 HDR、APNG、动画 WebP、多页图等会明确报告。生成 GIF 受 256 色和二值透明限制，转换到低精度格式可能丢失精度。无损编码不能消除缩放、颜色转换或格式转换本身的信息损失。

## 内存、并发与预览

`BatchConfig` 默认最多 4 个 worker，所有活跃任务共享 1536 MiB 的资源预留预算。任务按实际画布、像素类型和编码工作区估算开销；大任务占用较多预算时自然降低并发。超出单项或共享预算的输入单独跳过，其他条目继续处理。

预算是调度估算，不是操作系统内存上限，也不包含全部驱动开销。最终验收统计应用及其子进程的实际工作集；Windows Private Bytes 单独记录，不能视为驻留内存。当前实测和条件见 [验证记录](VALIDATION.md)。

GUI 线程不解码图片。预览后台使用有界请求队列，缩略图边长 128、普通预览边长 1024，缩略图缓存上限 64 项；切换工具清理显示缓存。GIF 顺序处理，避免全动画像素同时驻留。批处理期间暂缓额外预览解码。

Windows 使用短寿命子进程预热 Glow 着色器，以减少部分驱动在主窗口中保留编译工作区的开销；失败时回退到正常启动。该收益依赖 GPU/驱动，详见 [原生界面与内存决策](adr/0002-native-processing-and-memory.md)。

## 输出与便携设置

输出目录与输入分开，保留相对目录结构，同名结果追加编号。核心先写临时文件，成功后以不覆盖已有文件的方式提交；来源变化、硬链接别名、失败与取消均有独立处理。取消后保留已完成输出，未完成结果不提交。

`portable.flag` 启用便携设置：GUI 把参数写到程序旁的 `Data/settings.json`，默认输出为旁边的 `Output`。程序目录内的位置按相对路径保存，便于 U 盘移动；设置保存失败保留旧配置并显示错误。没有标记时使用普通用户配置目录。更多说明见 [便携使用](PORTABLE.md)。

## 扩展约束

增加工具时为其定义独立偏好、请求生成规则和会话，复用后台核心与有界预览。为跨工具输入来源和取消逻辑保留回归覆盖。引入新编码器或功能前检查其资源需求和许可证；依赖大型 AI 模型的去背景功能不属于当前范围。
